§4.1 client opening handshake MUST:

- Valid HTTP request (RFC 2616).
- Method GET; HTTP version at least 1.1.
- Host present.
- Upgrade value MUST include the "websocket" keyword.
- Connection value MUST include the "Upgrade" token.
- Sec-WebSocket-Key MUST be present: randomly selected 16-byte nonce, base64-encoded; selected randomly per connection; MUST NOT appear more than once (§11.3.1).
- Origin MUST be present if the client is a browser; MAY otherwise.
- Sec-WebSocket-Version MUST be 13 (§11.3.5).
- Sec-WebSocket-Protocol and Sec-WebSocket-Extensions MAY be present.

§4.1 client validates the server 101: Upgrade is an ASCII case-insensitive match for "websocket"; Connection contains a token that is an ASCII case-insensitive match for "Upgrade".

Header field names in requests and responses are case-insensitive (RFC 2616).

§4.2.1 server reading: if the handshake does not match (including ABNF), the server MUST stop and return an HTTP error (e.g. 400). Required parts:

- HTTP/1.1 or higher GET.
- Host.
- Upgrade containing "websocket", ASCII case-insensitive.
- Connection that includes the token "Upgrade", ASCII case-insensitive.
- Sec-WebSocket-Key: base64 value that decodes to 16 bytes.
- Sec-WebSocket-Version value 13.

§1.3 example (non-normative) shows GET with Upgrade: websocket, Connection: Upgrade, Sec-WebSocket-Key, Sec-WebSocket-Version: 13.
